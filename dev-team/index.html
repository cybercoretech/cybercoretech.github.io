03 / WORKING AGREEMENT

Clear standards.
Room to learn.

We evaluate contributions by the care and reasoning behind them, not by a résumé or a fixed number of years.

What we ask

  • Communicate respectfully and share progress when plans change.
  • Use issues and pull requests to explain the problem and proposed change.
  • Follow each project’s setup, style, tests, and licensing requirements.
  • Keep changes focused; add or update tests and docs when relevant.
  • Never submit secrets, copied code without compatible rights, or work you cannot license.

What helps

  • Git basics: branches, commits, reviewing feedback, and pull requests.
  • Experience in one relevant area; learning in public is welcome.
  • A link to a project, patch, design, or document you worked on—optional.
  • Interest in an issue or a clear first contribution idea.
  • Reliable async communication; availability can be just a few hours some weeks.

Security: Never include passwords, API keys, or vulnerability details in an application or public issue. Send vulnerability reports only to security@cybercoretech.net.
